# Audit of the original code (September 2026)

The original scripts are preserved unchanged in `legacy/`. This file records what was
wrong with them and how each problem was verified, so that none of the old numbers
make it into the paper.

**Bottom line:** none of the headline results in the original README or
`researchpaper.md` were produced by the code. The trained network was all-NaN, the
metrics hid that, and the LLM strategy had no effect on the control signal.

## Critical findings

| # | Problem | Evidence | Consequence |
|---|---------|----------|-------------|
| 1 | **The trained PINN is entirely NaN.** Training rolled out explicit Euler with `dt = 15/199 ≈ 0.075 s` on a system with ω ≈ 60–100 rad/s (ω·dt ≈ 4.7; Euler is unstable above 2). | Loading `legacy/models/pinn_model.pt`: **8834 / 8834 parameters are NaN**. | Every "PINN" and "Hybrid" result was computed with a dead network. |
| 2 | **`np.nanmax` hid the NaNs.** The PINN and Hybrid trajectories went to NaN after the first step, so the "peak" was simply the initial condition. | `legacy/outputs/experimental_results.json`: PINN = Hybrid = **exactly 20.0 mm / 8.0°**, which is `x0 = [0.02, 8°]`. | The pipeline printed "Divergence Prevented" even though the controllers produced NaN. |
| 3 | **The LLM strategy never reached the controller.** `HybridController.compute_control` ignored `current_strategy`; the strategy only changed training hyperparameters (learning rate, loss weights), and no training happens at run time. | Code inspection (`legacy/phase3_llm_integration.py`, line 219). | "Hybrid" was identical to "PINN-only" by construction. |
| 4 | **"API mode" was a stub.** `_api_response` returned the keyword-rule result. | Code inspection (line 192). | No real LLM was ever called. |
| 5 | **Aerodynamic matrices were dimensionally wrong.** Lift depended on plunge *displacement* (it must not), several terms had wrong powers of `b`, and Theodorsen's C(k) was reduced to its real part at a fixed k = 0.1. | Derivation vs Theodorsen / Hodges & Pierce. | The flutter speed (89.65 m/s) was not meaningful. |
| 6 | **Baseline and Hybrid used different plants.** The baseline used `k = 0.1`; the hybrid used `k = ω_h b / V` and a different integrator. | Code inspection. | The comparison was not like-for-like. |
| 7 | **State clipping to ±1 hid divergence.** `simulate()` returned `np.clip(sol, -1, 1)`. | `legacy/outputs/test_comparison_results.png`: the baseline is a square wave at ±1000 mm. | Physically meaningless trajectories. |
| 8 | **The training history plot was empty.** `loss_history` was never appended inside the training loop. | `legacy/outputs/pinn_training_history.png` is blank. | No training diagnostics. |
| 9 | **The "PINN" was not a PINN.** The physics-loss weight was 0; the loss was energy along an Euler rollout. That is policy optimisation through a (broken) simulator, not a physics-residual PINN. | Code inspection. | The method name in the paper would be wrong. |
| 10 | **Time was a policy input.** The network took absolute time `t`, which makes a feedback law time-varying and extrapolates beyond the training window. | Code inspection. | Not a valid feedback controller. |

## Documentation findings

- `README.md` "Expected Results" (80 → 40 → 25 mm, 69 %/38 %/33 %) and the table in
  `researchpaper.md` (78.3 / 42.1 / 26.4 mm, etc.) **do not come from any code run**.
  Do not cite them.
- Different files disagree on the flutter speed (55.05, ~5, 89.65 m/s).
- "First integration of LLMs with PINNs for closed-loop control" is an unverified
  novelty claim. Do a literature search before using any "first" wording.
- `requirements.txt` was a full environment freeze (130 packages, including unrelated
  ones such as pygame, opencv and openai) rather than the project's dependencies.

## What replaced it

See `docs/Architecture.md`. In short:

- a validated 6-state Theodorsen/Wagner model (matches an independent p-k analysis to
  within 1 %, and reproduces the Hodges & Pierce benchmark);
- exact ZOH discretisation shared by every controller;
- a discrete LQR baseline;
- a neural policy trained through the differentiable physics;
- a supervisor whose decisions actually change the control, with honest failure
  reporting and 30+ tests.
